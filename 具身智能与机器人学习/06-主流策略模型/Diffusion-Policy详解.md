# Diffusion Policy（DP）

> **定位**：人形端到端栈 **L6 策略层**的通用操作标杆。Columbia/TRI（RSS 2023）——把图像生成里的扩散模型搬来生成**动作**，是当前模仿学习最主流的底座（DP3、RDT-1B 都从它出发）。本篇教学目标：**搞懂"为什么扩散适合动作、怎么从噪声一步步变出动作"**。
>
> 前置：[[扩散模型基础]] [[动作空间表征总览]]。对比：[[ACT算法详解]]。升级版：[[DP3-3D扩散策略]]。

## 一、问题背景：为什么高斯策略不够

模仿学习的经典做法是学一个单峰高斯策略 $\pi(a|o)$（像 ACT 解码端的单峰输出）。但真实动作分布是**多模态**的：

- 同一观测，抓取动作可以从左绕、从右绕、从上探
- 单峰高斯只会输出"平均动作"——既不是左也不是右，反而**抓不到**

**扩散模型天然适合**：它学习任意复杂的多峰分布，能从噪声里"变出"动作分布的任意一种模式。

## 二、核心直觉：把"生成图像"换成"生成动作"

图像扩散 = 从噪声图逐步去噪出清晰图（见 [[扩散模型基础]]）。DP 把"图"换成"**动作序列**"：

```
噪声动作序列 x_T（纯噪声）
  → 逐步去噪（条件：当前观测）
  → x_0（一条合理的未来动作轨迹）
```

**条件**（观测）决定了"在这个场景下该做什么动作"，所以同一个模型在不同观测下生成不同动作。

## 三、架构

```
观测 o_t（最近 2 帧 RGB + 本体感觉）
  → 条件编码器（ResNet/ViT/CNN）→ c
噪声 x_T ~ N(0,1)
  → U-Net / Transformer 去噪网络（条件：c, 噪声步 k）
  → x_0 = 未来 16 步动作块 A_t
```

- **输入**：最近 2 帧 RGB + 本体感觉（给策略"最近的趋势 + 当前姿态"）
- **输出**：未来 16 步 EEF 相对增量（action chunking，见 [[动作空间表征总览]]）
- **骨干**：图像扩散用 U-Net；动作序列（1D 时序）可用 U-Net 或 ViT（见 [[Transformer与注意力机制]]）

## 四、训练：预测噪声

```python
noise = randn_like(action_seq)          # 1. 采样真实噪声
k = randint(0, 100)                     # 2. 随机噪声步
noisy = add_noise(action_seq, noise, k) # 3. 对真实动作加噪
pred_noise = unet(noisy, k, cond=obs_encoder(obs))  # 4. 网络预测噪声
loss = MSE(pred_noise, noise)           # 5. 让预测噪声≈真实噪声
```

**核心**：不是直接回归动作，而是**预测"加了什么噪声"**。MSE 等价于去噪得分匹配（见 [[Score-Matching与SDE]]），所以 MSE 是扩散的自然选择（见 [[Policy与损失函数]]）。

## 五、推理：迭代去噪

```
x_T ~ N(0,1)
for k = T, ..., 1:          # 从噪声步 T 退到 0
    x_{k-1} = 去噪一步(x_k, 条件 c, 步 k)
输出 x_0 = 干净动作序列
```

- **DDPM**：100 步，慢但稳
- **DDIM**：10 步加速，≈20ms，实时可用（见 [[扩散模型基础]]）

## 六、滚动时域控制（Receding Horizon）

预测的 16 步动作**不全执行**：

```
时间 t：预测 [a_t, ..., a_{t+15}] → 只执行前 N 步
时间 t+N：用新观测重新预测 → 再执行前 N 步
```

- **为什么不全执行**：执行过程中环境在变（物体移动、干扰），旧预测会过时
- **N 的权衡**：N 大 = 平滑但反应慢；N 小 = 反应快但可能抖

## 七、与 ACT 的对比

| | ACT（CVAE） | Diffusion Policy |
|---|---|---|
| 动作分布 | 隐变量 + 单峰高斯 | **任意多模态** |
| 精细操作 | 一般 | **优秀** |
| 速度 | <5ms | 10-100ms（DDIM 10 步 ≈ 20ms） |
| 数据需求 | 中 | 更少 |
| 典型场景 | 双臂粗操作 | 精细/接触丰富操作 |

**结论**：DP 表达力更强、数据效率更高，但推理慢一点；ACT 快但表达力受高斯假设限制。两者不是取代，是按任务选。
