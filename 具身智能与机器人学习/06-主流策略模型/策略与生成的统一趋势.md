# 策略与生成模型的统一：从 Pipeline 到端到端大模型

> 2024-2025 年具身智能最深刻的范式转移：策略模型和生成模型不再分离，而是统一成一个大的「世界-动作」模型。

---

## 1. 传统范式 vs 统一范式

### 传统 Pipeline（即将过时）

```
视觉编码器 → 特征提取 → 独立生成引擎(CVAE/Diffusion) → 独立动作解码 → 动作
   │                         │                            │
   └── 专为感知训练──────────┴── 专为生成训练──────────────┴── 专为控制训练
```

**问题**：
- 三个模块独立训练，信息瓶颈逐层缩窄
- 视觉特征对「生成好动作」未必最优（它只优化了 ImageNet / CLIP 目标）
- 无法利用「预测未来状态」的生成能力来辅助当前决策

### 统一范式（当前前沿）

```
图像 + 语言指令 → [统一大模型] → 同时输出：未来视频预测 + 动作序列
                     │
                     ├── 世界模型能力：预测如果我执行这个动作，世界会变成什么样
                     ├── 策略能力：为了达成目标，我现在应该做什么动作
                     └── 共享表征：两者共用同一个隐空间，互相增强
```

**核心思想**：**"预测未来"和"决定动作"本质上是同一个能力——理解物理世界的因果律。**

---

## 2. 统一范式的三条技术路线

```
路线一：VLA 大一统
  RT-2 → OpenVLA → π₀
  特点：一个模型吞下图文，直接吐出动作
  关键词：Autoregressive Token / Flow Matching Head

路线二：世界模型即策略
  UniPi → SuSIE → Genie
  特点：先生成未来视频，再从视频中提取动作
  关键词：Video Diffusion + Inverse Dynamics

路线三：万物皆 Token
  Gato → RT-1 → RoboCat
  特点：图像、文本、动作、奖励全部 Token 化，一个 Transformer 搞定一切
  关键词：Multi-modal Multi-task Single Transformer
```

---

## 3. 路线一：VLA 大一统

### 3.1 核心思路

不再区分「视觉塔」、「生成引擎」、「策略头」——一个模型端到端地从像素预测动作。

```
传统:  图像 → CLIP特征 → Diffusion去噪 → 动作解码 → 动作
VLA:   图像 + 文本 → [One Big Model] → 动作
```

### 3.2 代表作

| 模型 | 统一方式 | 关键设计 |
|---|---|---|
| **RT-2** (Google, 2023) | VLM 输出 Token 直接当动作 | 动作离散化为 256 bins × 7 维 → 7 个 Token，LLM 自回归预测 |
| **OpenVLA** (Stanford, 2024) | 开源版 VLA 大一统 | SigLIP+DINOv2 → Llama2 → 动作头，支持 LoRA 微调 |
| **π₀** (Physical Intelligence, 2024) | Flow Matching 统一 | 从噪声到动作的一条 ODE，1-10 步推理，跨多种机器人形态 |
| **Octo** (UCB/Stanford, 2024) | 通用机器人 Transformer | 多 embodiment 联合训练，扩散头或自回归头生成动作 |

### 3.3 π₀ 的统一架构（最具代表性）

```
        π₀ 统一模型
┌─────────────────────────────────────┐
│                                     │
│  图像 ──→ ViT ──→ 视觉Token ──┐     │
│                                │     │
│  本体感觉 ──→ MLP ──→ 状态Token ─┤   │
│                                ├──→ [Transformer Backbone] ──→ 动作Token
│  语言指令 ──→ Tokenizer ──→ 文本Token ─┘                 │
│                                                          │
│  训练目标：Flow Matching Loss（不是分类、不是回归）         │
│  x_0 ~ Noise → Flow ODE → x_1 = 动作                     │
│                                                          │
│  关键：同一个 Transformer 既"理解场景"又"生成动作"          │
└─────────────────────────────────────┘
```

> 没有独立的"生成引擎模块"——**Transformer 本身就是生成引擎**。

## 4. 路线二：世界模型即策略

### 4.1 核心思路

如果模型能准确预测「我做动作 A 后世界会变成什么样」，那么它自然就能选出最优动作——**生成未来 = 隐式策略**。

### 4.2 代表作

| 模型 | 统一方式 | 关键设计 |
|---|---|---|
| **UniPi** (Google/MIT, 2023) | 文本 → 视频 → 动作 | ① 文本生成未来视频（Video Diffusion）② 从视频提取动作（Inverse Dynamics） |
| **SuSIE** (Stanford, 2023) | 子目标生成 + 执行 | ① Diffusion 生成中间子目标图像 ② 低级策略执行子目标 |
| **Genie** (Google DeepMind, 2024) | 视频 → 交互世界模型 | 从视频中学习可交互的世界模型，推理时在模型中"想象"动作后果 |

### 4.3 UniPi 的工作流

```
┌──────────────────────────────────────────────────────┐
│                     UniPi 统一流程                      │
├──────────────────────────────────────────────────────┤
│                                                      │
│  "拿起苹果" ──→ Video Diffusion ──→ 未来视频序列       │
│                                       │              │
│                                       ▼              │
│                              Inverse Dynamics Model   │
│                              (从相邻帧反推动作)         │
│                                       │              │
│                                       ▼              │
│                                  动作序列              │
│                                                      │
│  统一性：Video Diffusion 既是「世界模型」又是「规划器」   │
└──────────────────────────────────────────────────────┘
```

### 4.4 为什么世界模型 = 策略？

1. **隐式规划**：生成未来视频 → 检查是否碰到障碍物 → 选择安全路径 → 无需显式 RL
2. **零样本泛化**：见过「苹果在桌上」和「苹果被拿起」的视频，就能推理新场景
3. **视觉可解释性**：生成的未来视频就是决策的「可视化解释」

## 5. 路线三：万物皆 Token

### 5.1 核心思路

把图像、文本、关节角、力矩、奖励信号**全部离散化为 Token**，用一个超大 Transformer 做 Next-Token Prediction。

### 5.2 代表作

| 模型 | 输入 Token | 输出 Token | 关键创新 |
|---|---|---|---|
| **Gato** (DeepMind, 2022) | 图像 + 文本 + 本体感觉 + 动作 | 文本 + 动作 | 一个 1.2B Transformer 玩 Atari、聊天、控制机械臂 |
| **RT-1** (Google, 2022) | 图像 + 指令 Token | 动作 Token | 用 ImageNet 预训练 + 机器人数据微调 |
| **RoboCat** (DeepMind, 2023) | 图像 + 动作 Token | 动作 Token | 自我改进循环：训练→部署→收集数据→再训练 |

### 5.3 Gato 的统一哲学

```
输入序列（一个长 Token 流）:
[图] [图] [文] [文] [关节角] [关节角] [力矩] [力矩] [奖] [奖] ...

     ↓ 都是 Token，同一个 Transformer

输出序列:
[文] [文] [动作] [动作] [动作] ...
```

> **同一个 Transformer 处理所有模态，用同一个损失函数（Next-Token Prediction），玩 Atari 的同时还能跟你聊天。**

---

## 6. 为什么统一范式更好？

### 6.1 共享表征的乘法效应

```
独立训练:   视觉特征 ─→ 只有分类/检测有用
           生成特征 ─→ 只有去噪有用
           控制特征 ─→ 只有动作有用
           = 1 + 1 + 1 = 3

统一训练:   同一个隐空间同时服务于：
           感知 + 预测 + 规划 + 控制
           = 四个能力互相增强 > 4
```

### 6.2 具体优势

| 维度 | 传统 Pipeline | 统一大模型 |
|---|---|---|
| **表征复用** | 三套独立表征 | 一套共享表征，信息无损 |
| **数据效率** | 每个模块需各自训练 | 多任务联合训练，互相正则化 |
| **泛化能力** | 仅见过训练分布 | 世界模型能力 → 零样本推理未见过场景 |
| **涌现能力** | 无 | VLA 能理解「拿起将要掉落的物体」等抽象概念 |
| **推理速度** | 需等三个模块串行 | 单次前向（Flow Matching 1-10 步） |

---

## 7. 统一范式的技术挑战

| 挑战 | 当前解决方案 |
|---|---|
| **模型太大，推理太慢** | Flow Matching 少步推理、量化、蒸馏小模型 |
| **多 embodiment 数据异构** | Token 化统一接口 + 数据标准化（Open X-Embodiment） |
| **世界模型幻觉** | 在仿真中验证 + 不确定性量化 |
| **实时性 vs 精确性** | 分层架构：VLA 做高层规划（10Hz），低级策略做实时控制（100Hz+） |
| **长程规划** | 层次化世界模型（Hierarchical World Models） |

---

## 8. 未来方向

```
2022: Gato ──────────→ 证明"万物皆Token"可行
2023: RT-2, UniPi ──→ VLA大一统 + 世界模型即策略
2024: π₀, Genie ────→ Flow Matching统一 + 视频世界模型
2025+: ??? ──────────→ 全模态实时统一？10B参数跑在边缘设备？
```

**最可能的方向**：
1. **World Model + Policy 端到端联合训练**（不是先生成视频再提取动作，而是同一个 loss 同时优化）
2. **实时 VLA 部署**（Flow Matching 1 步推理 + TensorRT 量化 → 50Hz 端到端）
3. **多机器人经验共享**（跨 embodiment 的统一表征，新机器人零样本使用）
