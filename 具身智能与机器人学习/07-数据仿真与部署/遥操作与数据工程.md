# 遥操作与数据工程

> **机器人策略=模型×数据。** 数据是具身智能的最大瓶颈——高质量遥操作演示数据决定了策略性能的上限。

## 为什么遥操作数据是瓶颈？

| 维度 | 视觉/语言 | 机器人 |
|---|---|---|
| 数据来源 | 互联网(~10B级) | 需人工遥操作采集 |
| 采集成本 | 标注≈0 | 硬件+人力≈$100/小时 |
| 标注方式 | 自动/弱监督 | 动作标签(关节角/末端位姿) |
| 分布覆盖 | 长尾天然覆盖 | 仅覆盖演示者行为 |

**核心矛盾**：模仿学习需要成百上千条高质量演示轨迹，但遥操作采集效率低、成本高。ALOHA和LeRobot的出现正是为了解决这个瓶颈。

## ALOHA 架构

Stanford ALOHA 定义了低成本双臂遥操作的标准范式。

### Leader-Follower 架构

```
操作者操控Leader臂→Leader编码器读取关节角→镜像映射→Follower臂复现
                                                       ↓
                                                [4台相机录制RGB]
                                                       ↓
                                              时间戳对齐→单个轨迹
```

物理上完全对称的两组机械臂：Leader 带编码器供人操控，Follower 带电机执行动作。操作者移动 Leader，Follower 实时复现。

### 双臂镜像变换

Leader 与 Follower 面对面安装，需做 **镜像映射**：

$$\begin{bmatrix} x_{\text{follower}} \\ y_{\text{follower}} \\ z_{\text{follower}} \end{bmatrix} = \underbrace{\begin{bmatrix} -1 & 0 & 0 \\ 0 & -1 & 0 \\ 0 & 0 & 1 \end{bmatrix}}_{\text{镜像矩阵 } M \in \mathbb{R}^{3\times3}} \begin{bmatrix} x_{\text{leader}} \\ y_{\text{leader}} \\ z_{\text{leader}} \end{bmatrix}$$

其中 $M$ 将 Leader 的左右/前后方向取反（面对面镜像），高度方向 $z$ 保持不变。

### 关节空间映射

对于 4-DoF 臂 + 1-DoF 夹爪的单臂：

$$q_{\text{follower}} = q_{\text{leader}} + q_{\text{offset}}$$

- $q_{\text{follower}} \in \mathbb{R}^{14}$：Follower 14维绝对关节角（双臂14×1）
- $q_{\text{leader}} \in \mathbb{R}^{14}$：Leader 编码器读取的关节位置
- $q_{\text{offset}} \in \mathbb{R}^{14}$：标定偏差，由初始位姿对齐计算

### 控制频率

| 组件 | 频率 | 说明 |
|---|---|---|
| 关节编码器读取 | 50Hz | Leader 臂实时采样 |
| 动作镜像 | 50Hz | 零延迟同步到 Follower |
| 相机录制 | 50fps | 4台USB相机，RGB 480×640 |
| 轨迹存储 | 50Hz | 单条轨迹时长2-120s |

## 数据格式：HDF5 vs Zarr

遥操作轨迹数据的两种主流存储格式：

### HDF5（层次化数据格式）

```
trajectory.hdf5
├── /observations
│   ├── /images
│   │   ├── /cam_high (N,480,640,3) uint8
│   │   ├── /cam_left_wrist (N,480,640,3) uint8
│   │   ├── /cam_right_wrist (N,480,640,3) uint8
│   │   └── /cam_low (N,480,640,3) uint8     ← 可选俯视相机
│   └── /qpos (N,14) float32                  ← 关节位置
│   └── /qvel (N,14) float32                  ← 关节速度
├── /action (N,14) float32
└── /episode_ends (E,) int64                   ← 每条轨迹结束索引
```

**特点**：单文件存储、层级树结构、适合本地读写。ALOHA 官方默认格式。

### Zarr（分块云原生格式）

```
dataset/
├── data/
│   ├── first_1000_episodes
│   │   ├── episode_000000.zarr
│   │   │   ├── observation.state (T,14)      ← 本体感觉状态
│   │   │   ├── observation.images.cam_high (T,H,W,C)
│   │   │   ├── observation.images.cam_low (T,H,W,C)
│   │   │   └── action (T,14)                  ← 动作
│   │   ├── episode_000001.zarr
│   │   └── ...
│   └── ...
└── meta/
    └── info.json                              ← 数据集元信息
```

**特点**：每个轨迹独立文件、支持分块并行读写、原生适配云存储(S3/GCS)、按需懒加载。

### 对比

| | HDF5 | Zarr |
|---|---|---|
| 存储模型 | 单文件多数据集 | 每轨迹独立chunk |
| 并行写入 | ❌ 需全局锁 | ✅ 无锁并发 |
| 云存储 | 需复制整个文件 | ✅ 原生支持S3/GCS |
| 随机访问 | 需解压整块 | ✅ 按需加载分块 |
| 压缩 | gzip/lzf | Blosc（更快） |
| 代表项目 | ALOHA | LeRobot |

## LeRobot 数据集标准

LeRobot 定义了社区统一的机器人数据集规范，降低数据互操作成本。

### 标准结构

```python
from lerobot.datasets.lerobot_dataset import LeRobotDatasetMetadata

# 元数据：每个episode的长度、数据统计、采集参数
metadata = {
    "fps": 50,                                   # 采集频率
    "features": {
        "observation.state": {"shape": (14,), "dtype": "float32"},
        "action": {"shape": (14,), "dtype": "float32"},
        "observation.images.cam_high": {"shape": (3, 480, 640), "dtype": "uint8"},
    },
    "robot_type": "so100",                       # SO-100 / ALOHA 等
}
```

### 动作空间约定

LeRobot 统一使用 **增量末端位姿（delta EEF pose）**：

$$a_t = \texttt{[dx, dy, dz, drx, dry, drz, grip]} \in \mathbb{R}^7$$

- $dx, dy, dz$：末端执行器三维平移增量（m）
- $drx, dry, drz$：末端执行器三维旋转增量（rad，axis-angle 表示）
- $grip \in [0,1]$：连续夹爪开合（0=全开，1=全闭）

单臂 7 维，双臂 $7 \times 2 = 14$ 维。

### 加载代码（PyTorch 伪代码）

```python
import torch
from torch.utils.data import Dataset, DataLoader
from lerobot.datasets.lerobot_dataset import LeRobotDataset

class RobotImitationDataset(Dataset):
    """加载 LeRobot 标准数据集的 PyTorch Dataset。"""
    
    def __init__(
        self,
        repo_id: str,              # HuggingFace Hub repo，如 "lerobot/aloha_sim_insertion_human"
        delta_timestamps: dict,    # 观测窗口，如 {"observation.state": [0], "action": [16]}
        transform=None,
    ):
        # LeRobotDataset 是 HuggingFace Dataset 子类，支持流式加载
        self.dataset = LeRobotDataset(
            repo_id,
            delta_timestamps=delta_timestamps,
            image_transforms=transform,
        )
        self.action_horizon = 16   # 预测未来16步动作块

    def __len__(self):
        return len(self.dataset)

    def __getitem__(self, idx):
        item = self.dataset[idx]   # 返回一个episode片段
        
        # 观测：t时刻的状态 + 多视角图像
        obs = {
            "state": torch.tensor(item["observation.state"][0]),         # (14,)
            "images": {
                "cam_high": torch.tensor(item["observation.images.cam_high"][0]).permute(2,0,1),  # (3,H,W)
                "cam_low":  torch.tensor(item["observation.images.cam_low"][0]).permute(2,0,1),
                "cam_left": torch.tensor(item["observation.images.cam_left_wrist"][0]).permute(2,0,1),
                "cam_right":torch.tensor(item["observation.images.cam_right_wrist"][0]).permute(2,0,1),
            },
        }
        # 动作：未来16步末端位姿增量 (16, 14)
        action = torch.tensor(item["action"])  # shape: (horizon, action_dim)
        
        return obs, action
```

## 数据清洗流水线

```
原始轨迹→离群点去除→时间对齐→归一化→清洗后数据集
```

### 1. 离群点去除

基于统计方法过滤异常帧：

$$x \text{ 为离群点当 } |x - \mu| > \tau \cdot \sigma$$

- $\mu$：滑动窗口均值（窗口 $w=5$）
- $\sigma$：滑动窗口标准差
- $\tau = 3$：3-sigma 规则

过滤对象：关节角突变（>0.1rad/帧）、末端位姿跳变（>5mm/帧）、夹爪卡顿帧。

### 2. 时间对齐

多相机+关节编码器存在帧时间戳偏移，需做插值对齐：

```python
def temporal_align(images: list, states: list, timestamps: list):
    """将异步观测对齐到统一时间轴（以关节数据为基准）。"""
    aligned_images = []
    for cam_images, cam_ts in images:
        # 线性插值：找到最近两帧做加权平均
        aligned = [lerp(cam_ts, cam_images, state_ts) for state_ts in timestamps]
        aligned_images.append(aligned)
    return aligned_images, states
```

对齐后所有观测在同一时间戳，消除跨模态延迟。

### 3. 归一化

$$q_{\text{norm}} = \frac{q - q_{\min}}{q_{\max} - q_{\min}} \quad \text{或} \quad q_{\text{std}} = \frac{q - \mu_q}{\sigma_q}$$

| 策略 | 公式 | 适用 |
|---|---|---|
| Min-Max | $\frac{x - x_{\min}}{x_{\max} - x_{\min}}$ | 已知关节限位 |
| Z-score | $\frac{x - \mu}{\sigma}$ | 未知分布（LeRobot 默认） |
| 图像 | $x/255.0$ | RGB uint8→float |

## 扩展：从单人到众包遥操作

| 阶段 | 规模 | 方案 |
|---|---|---|
| **单人采集** | 10-100条 | 单操作者+单台ALOHA |
| **实验室众包** | 100-1000条 | 多操作者轮换，引入行为多样性 |
| **远程遥操作** | 1000+条 | VR控制器+低延迟网络+力反馈 |
| **众包平台** | 10000+条 | 统一硬件(SO-100 $ <$ $100)→社区贡献→HuggingFace Hub |
| **仿真增强** | ∞ | GR00T-Mimic, MimicGen→1条真机数据→N条仿真变体 |

**LeRobot 的贡献**：开源低成本臂 SO-100（$<$ $100物料成本）+ 标准化数据格式，使全球众包成为可能。

## 策略如何使用遥操作数据

### ACT 使用方式

```
遥操作轨迹(q_t, a_t)_{t=1..T} → 构建windows
                  ↓
[(o_{t-K:t}, a_{t:t+H})] → CVAE Encoder(z|o,a) → Decoder(a|z,o)
                  ↓
训练时: z~q(z|o,a)  (后验，利用动作真值)
推理时: z~N(0,I)     (先验，无动作真值)
```

ACT 的 CVAE encoder 在训练时**窥视**动作真值来推断隐变量 $z$，推理时则从标准正态采样。未清洗数据会导致 encoder 学到噪声模式，KL 散度崩溃。

### Diffusion Policy 使用方式

```
轨迹→[(o_t, a_{t:t+H-1})] → 扩散训练
                               ↓
                 噪声 a^K → U-Net(观测条件 c) → 去噪 T步 → 动作块 a^0
```

Diffusion Policy 对数据质量更鲁棒（多模态分布建模），但时间对齐误差会导致动作块内的帧间抖动。

### 数据质量对策略的影响

| 问题 | ACT | Diffusion Policy |
|---|---|---|
| 关节编码器噪声 | KL崩散，生成抖动 | 扩散过程天然抗噪 |
| 时间对齐误差 | 跨模态误解，精度下降 | 动作块内部断裂 |
| 操作者风格不一致 | 高斯先验无法覆盖 | 多模态分布建模✅ |
| 数据量少(<50条) | 需 warm-start | 仍需≥20条 |
