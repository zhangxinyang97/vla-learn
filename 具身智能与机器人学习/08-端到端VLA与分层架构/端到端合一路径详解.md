# 端到端合一路径详解

> **定位**：人形端到端栈 **L6 合一路线**的教学拆解。回答：**"一个模型从观测直接出关节动作"到底是怎么做到的、难在哪、和分层到底差在哪。**
>
> 前置：[[VLA大模型]] [[端到端与分层架构之争]] [[分层架构总览-从意图到执行]]。延伸：[[2025-VLA新进展盘点]] [[端到端VLA模型盘点-下]]。

## 一、什么是"合一"

端到端合一 = **去掉人类定义的分层接口，让一个网络直接从观测映射到动作**：

```
分层： 图像+语言 → [VLM] → 目标位姿 → [规划/控制] → 关节动作
合一： 图像+语言+本体 → [一个 VLA 网络] → 关节动作（无中间显式接口）
```

"合一"的极致是 Gato 式的"万物皆 Token，一个 Transformer 学到底"（见 [[策略与生成的统一趋势]]）。

## 二、合一的关键设计：动作空间

合一路径最重要的选择是**网络直接输出什么**——这决定了整个训练与泛化（见 [[动作空间表征总览]]）：

| 动作空间 | 代表 | 特点 |
|---------|------|------|
| EEF 增量（7 维） | OpenVLA | 简单、需下游 IK 解关节角（严格说还不是"全身合一"） |
| 关节角/关节流 | π0 / π0.5 | 直接输出全身关节目标，Flow Matching 生成 |
| 统一动作空间（跨机器人） | RDT-1B / GO-1 / GR-2 | 把不同机器人的关节对齐后联合训练，跨本体迁移 |

**为什么"统一动作空间"是关键**：要一个模型控制多种人形/臂，必须把所有机器人的动作对齐到**同一套物理语义**（哪根关节、朝哪转、转多少），否则数据无法合并训练（RDT-1B 的思路，见 [[双手操作与协调]]）。

## 三、为什么"合一"没有想象中那么"端到端"

一个常见误解：合一路径 = 直连电机、不要任何低层控制。**实际上不是**：

```
π0 输出 → 关节目标位置（50Hz）
        → 低层 PD 控制器跟踪（1kHz）→ 电机
```

- VLA 推理一次 100ms+，不可能直接跑 1kHz 电机闭环
- 所以"合一"合的是**策略层**（省掉显式的规划/IK 中间层），但**低层关节控制仍由 PD/力矩环兜底**

**换句话说**：分层把"规划/控制"显式写出来，合一把它们**隐式学进网络**，但两者都离不开最底层的执行器控制。这与 [[人形硬件与系统构成]] 的频率金字塔完全一致。

## 四、合一的优势与代价

| 维度 | 合一 | 分层 |
|------|------|------|
| 信息保留 | 全程可微，不丢信息 | 接口压缩信息 |
| 可解释 | 黑盒，难定位错误 | 逐层可查 |
| 泛化潜力 | 上限高（scale 数据） | 受限于接口设计 |
| 数据需求 | 巨大（全身动作数据稀缺） | 每层可少数据 |
| 安全/调试 | 难 | 易 |

## 五、合一为什么要靠"后训练 RL"补

纯模仿（看人做）学到的合一策略天花板是"演示水平"。要超越，需要 **RL 后训练**：

- **π0-RL**：在 π0 上做 RL 微调，用自动奖励拆解任务
- **RST**：用语言模型生成奖励，对 RT-2 做 RL
- 见 [[2025-VLA新进展盘点]] 第三节

**逻辑链**：合一模型 = 预训练（OXE 等大量数据学"通用行为"）+ 后训练（RL 学"做得更好"）——这正对应 [[强化学习基础-贝尔曼方程与动态规划]] 里 RL 的定位。

## 六、整身合一的代表工作

| 工作 | 动作空间 | 亮点 |
|------|---------|------|
| π0（PI） | 关节流（Flow Matching） | 单臂/双臂/移动操作统一 |
| π0.5（PI） | 关节流 | 开源、跨 embodiment、后训练 |
| GO-1（智元） | 统一动作空间（ViLLA） | 多 embodiment 统一 |
| GR-2（字节） | 整身 | 视频预训练 + 动作微调 |
| GR00T N1（NVIDIA） | 双系统（语言推理 + 快速动作） | 人形、开源 |
