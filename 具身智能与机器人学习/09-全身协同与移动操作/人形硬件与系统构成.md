# 人形硬件与系统构成

> **定位**：人形端到端栈 **L8 的硬件底座**。知道一台人形机器人由哪些部件组成、各自干什么、怎么连起来，才能理解"策略输出最后落在哪里""1kHz 低层控制 vs 50Hz 策略是什么关系"。纯学习/仿真路线无需真机，但**理解硬件约束**能少踩很多仿真里的坑。
>
> 关联：[[人形机器人开源框架]] [[从策略输出到真机执行]] [[状态估计与传感器]]。

## 一、一台人形机器人由什么组成

```
┌─ 感知层   相机(RGB-D) · IMU · 关节编码器 · 足底力 · 触觉
├─ 计算层   机载 GPU/CPU（Jetson Orin 等）· 实时控制 PC
├─ 执行层   关节执行器（电机+减速器+编码器+力矩传感）
├─ 通信层   CAN / EtherCAT（关节）· 以太网/USB（相机）
└─ 能源层   电池 + 电源管理（高压驱动 + 低压逻辑）
```

## 二、执行器：人形的"肌肉"

| 组件 | 作用 |
|------|------|
| **电机** | 输出力矩（BLDC 无刷电机，FOC 电流环控制） |
| **减速器** | 放大扭矩、降速（谐波/行星/摆线；高减速比精度高但柔顺差） |
| **编码器** | 测关节角（输出侧/输入侧双编码器） |
| **力矩传感器** | 测关节力矩（做柔顺/力控） |

### 位置控制 vs 力矩控制（关键概念）

| 控制模式 | 含义 | 适用 |
|---------|------|------|
| **位置/速度控制** | 下发目标位置，驱动器内部闭环 | 精确轨迹、简单操作 |
| **力矩控制** | 直接下发目标力矩 | 接触、冲击、柔顺（阻抗控制） |

> **为什么人形需要力矩控制**：走路落地有冲击、抓取要柔顺——纯位置控制硬碰硬会抖甚至损坏。RL 策略通常输出"关节目标位置"交给低层 PD，或输出力矩——两种都依赖执行器能力（见 [[正逆运动学与PID控制]] 的阻抗控制部分）。

## 三、控制层级与硬件的对应关系

人形的控制是**分层分频**的，每层跑在不同频率、不同计算单元：

| 层级 | 频率 | 干什么 | 跑在哪 |
|------|------|--------|--------|
| 低层（关节控制） | 1000 Hz | 力矩/位置/速度环、FOC | 电机驱动器/实时 MCU |
| 中层（WBC/MPC） | 100-500 Hz | 全身控制、平衡 | 实时控制 PC |
| 高层（策略/VLA） | 10-50 Hz | 决策、动作生成 | 机载 GPU |

**这个频率金字塔是人形的"操作系统"**：高层想得慢但宏观，低层跑得快但只干机械活。VLA 推理 100ms+ 只能当高层，落地靠低层兜底（见 [[从策略输出到真机执行]]）。

## 四、通信与实时性

- **EtherCAT / CAN**：关节级实时总线（微秒级周期、确定性）
- **以太网 / USB**：相机等大带宽传感器（非实时）
- **实时性**：WBC/MPC 若错过 1ms 周期会导致控制抖动甚至摔倒——所以低层要用实时系统（RTOS/实时 Linux）

## 五、开源人形速查

| 平台 | 特点 |
|------|------|
| **Unitree G1 / H1** | RL 生态最成熟（Isaac Lab 官方支持），商用化程度高 |
| **Booster T1 / T2** | 开源硬件资料多，社区活跃 |
| **GR00T 生态（NVIDIA）** | 软硬件+仿真+数据飞轮一体化（见 [[2025-VLA新进展盘点]]） |

> 纯学习路线：不用买硬件，在 Isaac Lab 里用现成人形 URDF 即可理解全部约束（关节限位、力矩限幅、延迟、频率）。

## 六、硬件约束如何反哺策略设计

| 硬件约束 | 对策略/控制的影响 |
|---------|------------------|
| 力矩上限 | 动作不能瞬时突变 → 需要平滑项/低通 |
| 关节限位 | 动作空间要 clip → 仿真里也要设 |
| 通信延迟 | RL 训练要加延迟随机化 |
| 传感器噪声 | 观测要加噪声随机化 |
| 相机帧率/延迟 | VLA 推理节奏要匹配 |
