# 足式运动与步态

> **定位**：人形端到端栈 **L7 的"腿"**。人形最难的移动能力——不是轮子滚，而是靠两条腿在欠驱动、接触切换中保持平衡地往前走。理解步态，才知道 [[人形仿真与RL训练]] 里那些 reward 项为什么那么设。
>
> 前置：[[机器人动力学基础]]（ZMP/接触力）、[[人形机器人全身控制-WBC与MPC]]。关联：[[移动操作-底盘与臂协同]]（腿 vs 轮）。

## 一、为什么走路比轮子难一个量级

1. **欠驱动**：脚和地面之间没有"关节"，只能靠重力+接触力驱动，不能直接"命令脚往前走"
2. **接触切换（离散事件）**：脚抬起/落地是不连续的，动力学方程在接触瞬间"跳变"
3. **高维 + 强耦合**：30+ 自由度，质心、动量、关节力矩全部耦合
4. **平衡是硬约束**：倒 = 任务失败（ZMP 出支撑域，见 [[机器人动力学基础]]）

## 二、步态的基本概念

| 概念 | 含义 |
|------|------|
| **步态周期** | 一次完整"迈步"的重复单元 |
| **支撑相（stance）** | 脚着地、承重的阶段 |
| **摆动相（swing）** | 脚离地、前摆的阶段 |
| **双支撑相** | 两只脚同时着地（人行走时有，跑步时消失） |
| **步频 / 步长** | 每秒步数 / 每步距离，决定速度 |
| **步态（gait）** | 支撑相与摆动相的时序模式（walk/trot/run） |

**核心约束**：任何时刻支撑脚的凸包必须包含 ZMP（否则翻倒）；支撑相里脚不能滑（摩擦力在摩擦锥内）。

## 三、两条技术路线

### 路线 A：传统——步态生成 + WBC/MPC 执行

```
步态生成器（足端轨迹 + ZMP 轨迹）
        ↓
MPC（滚动时域优化质心轨迹与落脚点）
        ↓
WBC（层级 QP 求关节力矩）
        ↓
关节执行
```

- 可解释、可证明稳定；换步态/地形要重调
- 代表：ZMP 步态规划、质心动力学 MPC（见 [[人形机器人全身控制-WBC与MPC]]）

### 路线 B：RL——直接学"怎么走"

- 用 RL 直接从状态输出关节目标/力矩，reward 引导出步态
- **优点**：天然适应复杂地形/扰动，Unitree H1/G1 的"野外行走"就是 RL
- **缺点**：黑盒、训练贵、sim-to-real 难（见 [[人形仿真与RL训练]]）

## 四、RL 步态是怎么被"训"出来的（教学）

一个典型 locomotion RL 任务的配方（这是理解人形 RL 的核心）：

| 组件 | 内容 |
|------|------|
| **观察** | 重力方向投影、关节角/角速度、命令速度、上一动作、步态相位 |
| **动作** | 关节目标位置（交给 PD）或力矩 |
| **reward 项** | ① 速度跟踪（朝命令方向走）② 存活（不倒）③ 姿态惩罚（保持直立）④ 动作平滑（不抽风）⑤ 能耗惩罚 ⑥ 脚抬离地面（防拖地） |
| **终止** | 摔倒（躯干触地/姿态角超限）→ episode 结束 |
| **随机化** | 质量、摩擦、地面起伏、外力扰动、观测噪声、延迟 |

**reward 是"教"的核心**：机器人最初只会乱动（随机探索），reward 逐步"引导"它发现"朝目标走 + 不摔"的组合。速度跟踪项让它往前走，姿态项让它直立，平滑项让它动作自然——每一项都对应人类直觉里的"怎么算走得好"。

## 五、关键难点与常见问题

| 难点 | 表现 | 对策 |
|------|------|------|
| **reward hacking** | 机器人用怪姿势"骗"奖励但不真走 | 加惩罚项、人工抽查、调权重 |
| **sim-to-real gap** | 仿真走得好，真机摔 | domain randomization + 真实观测 |
| **接触建模误差** | 仿真里"脚粘地"，真机滑 | 摩擦力随机化、接触参数辨识 |
| **高频振荡** | 关节抖 | 动作平滑项 + 低层 PD 调参 |
